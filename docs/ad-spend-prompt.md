# 広告費の出し先を決めるためのプロンプト

> 「Google 広告にお金を払うなら、本体（shikakumon.com）と Studio（studio.shikakumon.com）のどちらに出すか」を、
> 手元の実数で決めるためのもの。売上の構造が変わったとき（Studio で有料会員が増え始めた、
> A8 の報酬が大きく動いた、など）に回し直す。
> 初回実施: 2026-10-24（結果は `docs/ad-spend-decision-2026-10.md`）。

---

## プロンプト本文

あなたは小さな Web 事業の広告投資を判断するアナリストです。日本語でやり取りしてください。
シカクモン本体（リポジトリ `siken`）とシカクモン Studio（リポジトリ `shikakumon-studio`）のどちらに
**Google 広告（検索広告）の費用を使うべきか、または使うべきでないか** を決めてください。

### 運営者の状況

- 売上が実際に出ているのは本体のアフィリエイト（A8）だけ。Studio は Pro 月額 980 円・年額 9,800 円だが、運営者以外の有料会員はほぼいない。
- 目的は利益。流入を増やすこと自体は目的ではない。
- 「Google 広告」は、お金を払って集客する Google 広告（検索広告）のこと。本体は AdSense（広告を載せて収入を得る）の再審査中で、これは別の話として扱う。

### 前提として読むもの

- 本体: `docs/affiliate-growth-audit.md`（アフィリの構造と実測値）、`docs/career-affiliate.md`、`docs/ga4-events.md`、
  `src/lib/affiliate-links.ts`・`src/lib/smart-set-price.ts`・`src/lib/exam-dates.ts` のコメント（報酬率・成果条件・申込締切）。
- Studio: `docs/growth/brief.md`（28 日の実測）、`docs/growth/phase0.md` §2（DB・Stripe の実数）、
  `docs/growth/ga4-funnel-2026-10-10.md`、`docs/growth/log.md`（本番に出た変更と日付）、`lib/plan-guard.ts`（無料枠と原価）、`README.md`（API の上限）。
- 数字はこれらが一次情報。GA4・A8・Stripe・Google 広告の管理画面にはこのセッションから入れない。
  無い数字は「未確認」と書き、運営者に取ってもらう数字として最後に並べる。**推測を数字のように書かない。** 置いた仮定は「仮置き」と明記する。

### 決め方

1. **同じ物差しで比べる。** どちらも「広告 1 クリックあたりの期待売上」と「払うクリック単価（CPC）」の差で見る。
   - 本体: 1 クリック → 本体の閲覧 → アフィリのクリック → ASP の成果。期待売上は「A8 の確定報酬 ÷ 同じ期間の本体ユーザー数」。資格・時期で絞った値も出す。
   - Studio: 1 クリック → 着地 → 登録 → 有料化 → 継続月数。期待売上は「登録率 × 有料化率 × 1 人あたりの課金額」。無料会員の AI 原価も差し引く。
2. **損益分岐の CPC を出す。** 期待売上がそのまま上限 CPC になる。実数が無い項目は、取れたら計算できる式の形で残す。
3. **広告以外の手段と比べる。** 同じ数字を、お金を使わない施策（未マージの PR、本体からの送客の改善など）で動かせるなら、そちらが先。
4. **出すなら、小さく試す設計にする。** 対象・期間・キーワードの方針・着地ページ・予算の上限・止める条件・判定の日と方法。
5. **出さない方には、出してよくなる条件を書く。** 何の数字がいくつになったら回し直すか。

### 制約

- 読み取り専用で調べる。コードの変更・広告アカウントの操作・ASP の操作はしない。
- 本体の AdSense 関連（/q/ の noindex、sitemap、ads.txt、AdSense の meta、プライバシーポリシー、about）とアフィリ導線を削る提案はしない。
- ASP のプログラムごとに、リスティング広告の可否（自サイト経由の出稿・商標や指名のキーワード）が違う。確かめていない案件を「出せる」と書かない。
- Studio の価格・無料枠・トライアル条件の変更は提案にとどめる（Studio の `docs/growth/brief.md` の制約）。
- 「SEO を頑張る」のような抽象論は書かない。何をどう変えるかまで書く。

### 出力

1. 冒頭に結論を 3 行（どちらに出すか、どの範囲で、何を確かめてから）。
2. 2 つの選択肢の比較表（今の売上、売上までの段数、1 クリックの期待売上、損益分岐 CPC、リスク）。
3. 出さない方: 数字で何が起きるかと、出してよくなる条件。
4. 出す方: 小さく試す設計（上の 4）。
5. お金を使わずに先にやること。
6. 運営者に取ってもらう数字と確認事項のチェックリスト（どの管理画面のどこを見るか）。

結果は本体の `docs/ad-spend-decision-YYYY-MM.md` に書く。前回の判断書があれば、変わった数字と結論の差分を冒頭に書く。
