## 5.1 Safari の ITP による長期成果の取りこぼし(2026-09-05 追記)

A8 の実測で、クリックから 18〜47 日後に注文が発生している(比較して戻ってきた人が買っている)。
一方 Safari の ITP は A8 のクッキーを最長 7 日で消すため、Safari 経由の長期成果はほぼ計上されない。
クッキーの寿命はメディア側では延ばせず、根本対策は広告主の A8 ITP 対応(自社ドメインでの成果照合)。

こちらで実施したこと(効く順):

1. **再訪時の再クリック導線**: `AffiliateLink` のクリック時に資格と種類を端末内(localStorage・個人情報なし)に記録し、
   トップ・学習履歴・その資格のトップで `RecentCourseReminder` が「広告 前回チェックした講座」を1行出す
   (placement=`return_home` / `return_study` / `return_top`)。60日で消え、「非表示」で30日出さない。
   再訪でのクリックがクッキーを張り直し、購入が7日以内に収まる確率を上げる。
2. **購入直前に踏む場面**: 締切カウントダウンの無料オファー、締切10日前の一般コラム、模試結果の導線(§2)。
3. **着地を購入ページに近づける**: ITパス・ビジ法を協会の専用講座ページへ(§2)。
4. **損失の規模を測る(GA4 の手作業)**: 探索 → 自由形式 → ディメンション「ブラウザ」× 指標「イベント数」、
   フィルタ「イベント名 = affiliate_click」。Safari の比率がクリックに占める割合が、7日を超える成果の
   取りこぼし上限の目安になる。placement=`return_*` のクリック数が「踏み直し」の実数。

ユーザー側: A8 のプログラム詳細で アガルート / SMART に「ITP対応」の表示があるか確認し、無ければ
「広告主お問い合わせ」から ITP 対応の予定を尋ねる。

## 5.3 合格報告(利用者の声)の仕組み — 2026-09-05 実装

Ping-t の合格体験記にあたるもの。**掲載するのは実在の投稿だけ**で、自動公開の経路は作っていない。
運用手順は `docs/pass-report-ops.md`。

| 段 | 実装 |
|---|---|
| 収集 | `/goukaku-houkoku/` のフォーム → `POST /api/pass-report` → Resend で運営宛メール。保存しない |
| 審査 | 運営が読み、掲載可のものだけ `src/content/voices/*.md` に書き写す。非掲載条件はフォームにも明記 |
| 掲載 | `/voice/` 一覧と資格トップ(最新3件)。0件なら資格トップに何も出さず、`/voice/` は noindex かつ sitemap 対象外 |
| 依頼 | 試験日から45日以内だけ資格トップに出す。申込締切のカウントダウンと時期が重ならない |

設計の判断:

- **1件1URLにしない**。件数が2桁に届くまでは薄いページの量産になる。
- **`Review` / `AggregateRating` の構造化データを付けない**。星評価が無く、自社への自己言及レビューの構造化データはリスク。
- **不合格報告も同じ扱いで載せる**。合格報告だけが並ぶページは、それだけで作り物に見える。
- **謝礼を渡さない**。対価と引き換えの投稿はステマ規制の「利益提供秘匿型」の疑いを招く。
- **報告本文の教材名にアフィリリンクを貼らない**。投稿者の言葉を広告に変換する行為で「なりすまし型」と隣接する。講座CTAは報告カードの外に置く。
- **報告を根拠にした合格率を出さない**。数値の合格率は公式値のみ。

1件目をどう取るか: 直近の受験直後の窓は賃管士(11/15)・管業(12/6)・貸金(11月)。
この試験日の翌日に依頼CTAが出る状態にしておくことが、最初の報告を得る機会になる。
