# Cowork に渡すプロンプト（GA4 のキーイベントを studio_click に合わせる）

2026-11-15 作成。改善案「Studio へのクリックがキーイベントになっていない」を「やる」にしたので、GA4 の管理画面だけで済む変更を Cowork に頼む。コードとプライバシーポリシーは変えない（イベント名もパラメータも今のまま）。
下の枠を、そのまま Cowork に貼る。

| 枠 | いつ | 結果を受けて直すもの |
|---|---|---|
| 枠1 キーイベントの変更（変えてよい） | いつでも | CHANGELOG.md に実施日を書く（キーイベントは設定した日から先だけ数えられるので、日付が比較の区切りになる） |

## 枠1: キーイベントの変更

```
シカクモン（https://shikakumon.com）の GA4 で、キーイベントの設定を2つだけ変えてください。

## 守ること
- 変えてよいのは「管理 → データの表示 → キーイベント」の、下に書いた2つのイベントのマークだけ。ほかのキーイベント・イベントの作成や変更・カスタム定義・データ保持・リンク・ユーザーは変えない。
- 対象は GA4 プロパティ「シカクモン」（537254382）だけ。姉妹サイトのプロパティは触らない。
- 画面が説明と違う、イベントが一覧に無いなど、迷ったら変更せずに「未実施（理由）」と書いて終える。
- メールアドレスや氏名を報告に書かない。

## やること
1. GA4 のプロパティ「シカクモン」（537254382）を開く。
2. 変更の前に、管理 → データの表示 → キーイベント の一覧を見て、いまキーイベントになっているイベント名をすべて書き留める（11/15 時点では affiliate_click と purchase の2つのはず）。
3. studio_click をキーイベントにする。
   - 管理 → データの表示 → イベント の一覧に studio_click があれば、その行の「キーイベントとしてマークを付ける」をオンにする。
   - 一覧に無ければ、キーイベント の画面の「新しいキーイベント」でイベント名に studio_click（小文字・アンダースコア、綴りはこのとおり）を入れて保存する。
   - 「カウント方法」を選べる場合は「イベントごとに1回」（既定）のままにする。
4. purchase のキーイベントのマークを外す（イベント一覧の行のスイッチをオフ）。イベント自体は消さない。
5. affiliate_click はそのまま（キーイベントのまま）にする。
6. 変更のあと、もう一度キーイベントの一覧を見て、並んでいるイベント名をすべて書き留める。

## 報告の形
- 変更前のキーイベント: （イベント名を並べる）
- 変更後のキーイベント: （イベント名を並べる。affiliate_click と studio_click の2つになっているはず）
- studio_click のカウント方法: （イベントごとに1回 / セッションごとに1回 / 選べなかった）
- 実施した日時（日本時間）:
- うまくいかなかったこと・画面が説明と違ったこと: （無ければ「なし」）
```

## 結果を受けてやること

- 実施日を CHANGELOG.md に書く。キーイベントの合計は、この日から studio_click の分（28日で約1,200回）増えるので、前の期間と合計を比べるときは段差に注意する。
- 合格報告（pass_report_submit）は 10/18〜11/14 に届いていないので、今回はキーイベントに入れない。届き始めたら改めて考える。
