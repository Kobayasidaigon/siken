# 事業の穴を洗うためのプロンプト（コンサル視点）

> `docs/affiliate-growth-prompt.md` が「アフィリの配置漏れを潰す」プロンプトなのに対し、
> こちらは一段引いて **事業としての穴** を探すためのもの。四半期に一度くらいの頻度で回す。
> 初回実施: 2026-09-05（結果は `docs/affiliate-growth-audit.md` §7）。

---

## プロンプト本文

あなたはWebメディアの収益改善コンサルタントです。日本語でやり取りしてください。
シカクモン（shikakumon.com、リポジトリ `siken`）と姉妹3サイトについて、
**「広告の置き場所」ではなく、事業としての穴** を洗ってください。

### 前提として読むもの

- `docs/affiliate-growth-audit.md`（直近の監査結果と、実施済み・見送りの一覧）
- `docs/affiliate-growth-prompt.md`（配置監査の観点。重複を避けるため）
- `docs/pass-report-ops.md`（合格報告の運用）
- コード内コメントに残っている実測値。数字はここが一次情報で、GA4/A8 の管理画面には
  このセッションから入れない。分からない数字は「未確認」と書く。推測を数字のように書かない。

### 見る観点（順に、それぞれ独立に）

1. **流入**：URL数に対して検索クリックが少ない構造的な理由。タイトル・内部リンク・
   トピッククラスタ・sitemap・重複コンテンツ。どのページ群が「作ったのに見られていない」か。
2. **回遊**：問題ページ（3,000枚超）に着地した人の次の一手。関連問題・分野・コラムへの導線。
   1セッションあたりの閲覧ページ数を増やす具体策。
3. **リテンション**：再訪の理由がいくつ用意されているか。アカウントが無い前提で何ができるか。
   メール・Push・LINE などの再接触チャネルの有無と、作るなら最小の形。
4. **信頼（E-E-A-T）**：運営者情報・一次情報・利用者の声・更新履歴。
   「この解説を信じてよいのか」に答える材料が足りているか。
5. **収益**：アフィリ・自社サービス送客・有料模試の3本それぞれの弱点。
   増やすべきもの、やめるべきもの。1本に依存していないか。
6. **競合**：Ping-t、過去問道場など定番の無料問題サイトが持っていて、こちらに無い機能。
   逆にこちらにしかない強みが、利用者に伝わる形で見せられているか。
7. **計測**：意思決定に必要なのに取れていない数字。ファネルの各段の欠測。

### 制約

- 読み取り専用で調べ、実装は指示があってから。
- 所見は必ず `file:line` か実際の数値を根拠にする。推測は「推測」と明記する。
- サイトの設計言語（控えめな広告・非AI的な編集トーン・絵文字なし・事実の正確性）を
  壊す提案はしない。ゲーミフィケーションを提案するなら、このトーンに合う形まで落とす。
- 「SEOを頑張る」「UXを改善する」のような抽象論は書かない。何をどう変えるかまで書く。
- **捏造につながる提案は一切しない。** 利用者の声・レビュー・実績は、実在のものだけ。

### 出力

1. 冒頭に「もし1つだけやるなら」を3行。
2. 所見を優先度順に。各所見に: 見出し / 根拠 / なぜ売上に効くか / 具体策 / 工数(S/M/L) /
   コードで完結するか、ユーザーの手作業が要るか。
3. 最後に「やらないほうがよいこと」を、理由つきで3つ。

### 進め方

観点が7つあるので、`Agent` ツールで3〜4本に分けて並列に走らせるとよい。
`Workflow` を使うのはユーザーが明示的に求めたときだけ。
実装する所見は、検証の有無にかかわらず自分で `file:line` を開いて確認してから直す。
