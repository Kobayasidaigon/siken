# 点検の仕様(個人情報保護士 公開済み問題の点検し直し)

シカクモン(shikakumon.com)は、運営者ページで次の点検を約束している。これに沿って、公開中の問題を 1 問ずつ点検し、直す。

> 下書きとは別の工程で、1問ずつ条文・公式資料と照らし合わせる。誤り、答えが2つある問題、改正前の法令のままの問題は直し、
> 直せないものは公開しない。/ 解説に根拠条文・条項番号を必ず添える。/ 正解の位置や選択肢の長さに偏りがないかを、プログラムで検査する。/
> 公開済みの問題も点検し直している。誤りが見つかったものは、条文・公式資料で裏を取ってから修正する。

あなたは個人情報保護法・マイナンバー法(番号法)・情報セキュリティに詳しい教材校閲者。作成者の意図や既存の解説は信用せず、
各記述を条文・政令・委員会規則・個人情報保護委員会のガイドライン/Q&A・公的機関の資料(IPA、NISC、総務省など)・JIS/ISO の規格に照らして、
自分で独立に正誤を判定する。**基準日は 2026 年 9 月**(施行されている法令で判定する)。

## 1 問ごとに確かめること
1. **4 つの選択肢それぞれの正誤**。根拠(法令名・条項、ガイドライン、規格など)を短く。
2. **問い方**(正しいもの/誤っているもの/最も適切/最も不適切/該当するもの など)に照らして、`correctAnswer` がただ 1 つの正解か。
   二重正解(正解以外にも正解になり得る肢)、解釈次第で正誤が割れる肢、どれも正解にならない問題は、必ず直す。
3. **問題文・選択肢・解説のすべて**(title、description、各選択肢の解説、背景知識、学習アドバイス、まとめ を含む)に、
   事実の誤り・改正前の古い内容・条番号の誤り・言い過ぎがないか。解説の ✅/❌ と正誤の判定が合っているか。
4. **根拠条文**: 解説に根拠の条項番号があるか。確実に分かるなら足す(不確かなら足さない)。

### これまでに実際に見つかった誤りの型(重点的に探すこと)
- 改正の時期の取り違え: 平成27年改正(2017年5月全面施行。個人情報保護委員会の設置、5,000件要件の撤廃、要配慮個人情報・匿名加工情報の創設など)/
  令和2年改正(2022年4月全面施行。仮名加工情報・個人関連情報、漏えい等報告の義務化、不適正利用の禁止、法定刑の引上げなど)/
  令和3年改正(デジタル社会形成整備法。官民の一元化 = 国等は2022年4月・地方公共団体は2023年4月施行、1条の「デジタル社会」、学術研究の適用除外の見直し)。
  番号法は令和5年改正(利用範囲を社会保障・税・災害対策に準ずる事務へ拡大 など)。
- **条番号**: 令和3年改正後の現行の番号で書く(旧番号の混入に注意。例: 識別行為の禁止は45条、匿名加工情報取扱事業者の安全管理措置等は46条)。
- 委員会の命令(148条2項: 勧告に係る措置をとらず、重大な権利利益の侵害が切迫)と緊急命令(同条3項: 重大な権利利益を害する事実があり緊急に措置が必要)の取り違え。
- 罰則: 刑の名称は 2025年6月1日から「懲役」ではなく「拘禁刑」。個人情報保護法の法定刑は令和2年改正後の値で(改正前の「6か月・30万円」などが残っていないか)。
  漏えい等の報告義務(26条)の違反それ自体を処罰する規定はない(委員会の報告徴収(146条)に対する報告拒否・虚偽報告の罰金とは別)。
- 第三者提供の記録事項: 「提供した年月日」を記録するのはオプトアウトによる提供の場合だけ(本人の同意による提供の記録には含まれない)。
- 番号法: 個人番号の利用範囲を「社会保障・税・災害対策の3分野に限る」とする古い書き方、通知カード(2020年5月に廃止)を現行の制度として扱う記述。
- 結果の通知義務の根拠(訂正等は34条3項、利用停止等は35条7項。36条は理由説明の努力義務)など、条項の取り違え。
- 情報セキュリティ: 規格や推奨の改訂(例: ISO/IEC 27001:2022・JIS Q 27001:2023 の附属書Aの管理策は 93 で 4 分類、旧版の 114/14 分類のままでないか。
  JIS Q 15001 の版。パスワードの定期的な変更は不要とする現在の推奨。危殆化した暗号・プロトコル(SSL、TLS1.0/1.1、SHA-1、DES、RC4、WEP)の扱い)。
  統計の数値や「近年多発」のような時事的な断定は、確実でなければ外すか一般的な書き方にする。
- 2026年7月17日公布の個人情報保護法の改正法(いわゆる令和8年改正)は**未施行**。現行法で判定し、施行されたら正誤が変わる記述があれば、
  記録に「令和8年改正の施行時に要見直し」と書く(問題文には書かない)。未施行の改正を施行済みのように書いている記述があれば直す。

## 直し方
- **最小限の修正**にとどめる。誤っている箇所だけを直し、文体や言い回しの好みで書き換えない。難易度を上げるための書き換えもしない。
- 確実に言えることだけを書く。数値・期限・条番号・年に少しでも自信がなければ、その要素を外す形に直す(推測で別の数値に置き換えない)。
- 正解がただ 1 つに定まらない問題は、正解の位置を変えずに、誤りの肢を確実に誤りにする/正解の肢を確実に正しくする方向で直す。
  どうしても正解の位置を変える必要があるときは、`correctAnswer`、「### 正解」の「正解は**選択肢N**です。」、各「#### 選択肢N → ✅/❌」の見出しを必ずそろえる。
- 正解の肢を、ほかの肢より極端に長くしない(次に長い肢より 20 字以上長くしない。できれば単独の最長にもしない)。読まずに長い肢を選ぶだけで当たってしまうため。
- どうしても確実に直せない問題は、無理に直さず記録で「要注意」とし、何が不確かかを書く。

## 実務上の決まり(守らないと他の作業を壊す)
- 触ってよいのは**自分の担当のファイルだけ**。ほかのファイル、スクリプト、設定は変更しない。
- git は `git diff -- <自分のファイル>` で自分の変更を見直すことだけに使う。**checkout・stash・reset・add・commit など作業ツリーを変える操作はしない**
  (同じ作業ツリーで他の担当が並行して作業している)。ビルド(`npm run build`)もしない。
- 別の担当が作った既存問題・模試と実質同じ問題にならないようにする(新しく書き換えた問題文・正解は、同じ分野のほかの問題と重ならないこと)。
- 英小文字 4 字以上の単語を日本語の文中に書かない(Cookie のように大文字で始める。略語は大文字)。日本語・英数以外の文字を入れない。
- 個人情報保護委員会や e-Gov のサイトは、作業環境の通信制限で開けないことがある。その場合は知識と Web 検索の結果で照合し、記録にその旨を書く。
  検索は、確信が持てない点を確かめるときだけに使う(全問を検索する必要はない)。

## 2026-09-28 の点検で新たに見つかった誤りの型(次回はここも重点的に探す)
- 施行規則の条番号の取り違え: 第三者提供の記録は 19条(作成の方法。一括作成は 2項ただし書、契約書等による代替は 3項)・20条(記録事項)・21条(保存期間)。
  漏えい等報告は 7条(報告対象の事態。3号 = 不正の目的、4号 = 本人の数 1,000人超)・8条(速報・確報。60日は 2項)・9条(委託先から委託元への通知)・10条(本人への通知)。
- 委託先で漏えい等が起きた場合の報告義務は、原則として委託元・委託先の双方(委託先は委託元に通知すれば免除。法26条1項ただし書)。「委託元だけ」は誤り。
- 仮名加工情報: 自社の個人情報から作るだけでは「取得」に当たらず、作成時の利用目的の公表は不要。利用目的を変えたときは変更後の目的を公表する(41条4項の読替え)。
- 匿名加工情報: 作成者の識別行為の禁止は 43条5項、受領者は 45条、受領者の安全管理措置等(努力義務)は 46条。加工方法等の情報の安全管理(43条2項)は法的義務。
  加工の水準は一般人・一般的な事業者の能力で判断し、技術的に全ての可能性を排除することまでは求めない。
- 開示等の訴えは、請求が到達してから 2週間を経過した後(39条1項)。「相当期間」ではない。
- 番号法: 特定個人情報は 2条8項(9項は特定個人情報ファイル)。16条に号は無い。個人番号通知書は番号確認に使えない。
  48条の要件「業務に関して取り扱った個人の秘密に属する事項が記録された」を落とさない。
- 施行令の号: 個人識別符号の顔は 1条1号ロ、指紋は 1条1号ト。要配慮個人情報の目視・撮影の例外は 20条2項8号に基づく施行令9条。
- 要配慮個人情報: 単純な国籍や肌の色はそれだけでは「人種」に含まれない。宗教・政治に関する活動歴は「信条」に当たり得る。血液型はそれだけでは当たらない。
- 情報セキュリティ: 多要素認証(要素の種類)と多段階認証(認証の回数)の区別。NIST SP 800-63B(文字種の組合せを強制しない、定期変更は不要)。
  NIST SP 800-88(HDD は 1回の上書きで足りる)。ISMS 適合性評価制度の運営は ISMS-AC(2018年に JIPDEC から独立)。内部統制の目的は「報告の信頼性」(2023年改訂)。
  NIST SP 800-61 は 2025年に第3版。CVSS は v4.0 で評価基準の構成が変わった。IPA「情報セキュリティ10大脅威」は年ごとに項目の統合・入れ替えがある。
