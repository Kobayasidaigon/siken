pii-m2-051 / 問題なし / 正解の肢は JIS Q 27000:2019 の 3.28「情報セキュリティ」の注記と一致(機密性・完全性・可用性に加え、真正性・責任追跡性・否認防止・信頼性)。可用性・否認防止として書かれた定義は、実際には完全性・機密性の定義なので、この 2 肢は誤り。
pii-m2-052 / 修正 / 誤りなし。解説の「委託元の監督義務は残る」に根拠条文「(個人情報保護法25条)」を足した。回避・低減・移転・保有の 4 分類は一般的な整理で、正解は 1 つに定まる。令和8年改正で委託先に固有の規定(30条の3 など)が新設されるが、委託元の 25 条の義務についての記述は影響を受けない見込み。
pii-m2-053 / 修正 / 解説の「CVSS は基本・現状・環境の 3 つの評価基準からなる」はバージョン3の構成。バージョン4.0(FIRST が 2023 年 11 月に公開)では、現状評価基準が脅威評価基準に改められ、スコアに影響しない補足評価基準が加わった。そこで「バージョン3では…からなる。バージョン4.0では現状評価基準が脅威評価基準に改められ、スコアの算出に用いない補足評価基準が加えられた」と直した。評価基準の名称は、IPA「共通脆弱性評価システムCVSS概説」の検索結果で照合。どちらのバージョンでも各肢の正誤は変わらない。
pii-m2-054 / 問題なし / 脆弱性診断は既知の脆弱性の網羅的な洗い出し、ペネトレーションテストは侵入できるか(目標に到達できるか)の検証、という一般的な区別どおり。
pii-m2-055 / 問題なし / SBOM は構成部品・依存関係・バージョン・ライセンスの一覧で、外部ライブラリも含む。影響調査を容易にするものの、脆弱性への対処そのものは別に必要。
pii-m2-056 / 問題なし / RTO は目標復旧時間、RPO は目標復旧時点。2 つを取り違えた肢と、同じ意味とする肢は誤り。
pii-m2-057 / 問題なし / 3-2-1 の考え方。肢の「3つの複製」は一般的な言い方(「コピーを3つ」)。本来は原本を含めて 3 つと数える整理で、解説は「データを3つ保持し」と正しく書いている。ほかの肢は明らかな誤りで、正解は 1 つ。
pii-m2-058 / 修正 / 誤りなし。解説の「報告と本人への通知が必要になりうる」に根拠条文「(個人情報保護法26条1項・2項)」を足した。ランサムウェアで暗号化され復元できなくなれば「毀損」にあたり、不正の目的による漏えい等は規則7条3号の報告対象なので、記述は正しい。二重恐喝が一般的という記述は、警察庁の公表(手口が判明した被害の多くが二重恐喝)と合う。令和8年改正の施行時に要見直し(本人通知に例外が加わり、規定の位置も見直される。記述は「なりうる」なので施行後も成り立つ見込みだが、条項番号を確認すること)。
pii-m2-059 / 問題なし / 原本を保全して複製を解析し、ハッシュ値で同一性を確認する。管理の連鎖(誰がいつ扱ったかの記録)も含め、フォレンジックの基本どおり。
pii-m2-060 / 問題なし / CSIRT の役割(受付・分析・調整・窓口)。一般の事業者に CSIRT の設置を義務づける法律はない。
pii-m2-061 / 問題なし / SOC はログの常時監視と検知、CSIRT は対応の調整、と役割が異なる。
pii-m2-062 / 修正 / 誤りの肢「送信ドメイン認証を導入すれば、受信したメールの本文の改ざんを防止できる」の正誤が割れうる。送信ドメイン認証に含まれる DKIM は本文の改ざんを検知でき(063 の解説もそう説明)、「防止」を緩く読むと正しいとも取れるため。そこで「SPFを導入すれば、送信元の検証に加え、受信したメールの本文の改ざんも検知できる」に直し、確実に誤りにした(SPF が検証するのは送信元の IP アドレスで、本文は対象外)。解説も「SPF は本文を検証しないため改ざんは検知できない(改ざんの検知は電子署名を用いる DKIM が担う)」と合わせた。正解(SPF の定義)の位置は変えていない。
pii-m2-063 / 問題なし / DKIM は電子署名で送信元の正当性と改ざんの有無を確かめる仕組み。DMARC は、検証に失敗したメールの取扱い方針(何もしない・隔離・拒否)をドメイン所有者が宣言し、レポートを受け取る仕組み。
