# 「自分の学習データを見られる機能」の次を探すためのプロンプト

> 2026-10-24 作成。初回実施: 2026-10-24（結果は `docs/self-data-features-research.md`）。
> シカクモンは「自分が解いた問題をデータとして見る」機能（学習履歴 `/study/`）を持っている。
> その延長で、**利用者が喜ぶ機能がほかにないか** を調べるためのプロンプト。
> `docs/growth-consulting-prompt.md` が事業の穴を探すのに対し、こちらは利用者の体験から機能を探す。

---

## プロンプト本文

あなたは学習サービスのプロダクトリサーチャーです。日本語でやり取りしてください。
シカクモン（shikakumon.com、リポジトリ `siken`）に、**利用者が「これは助かる」と思う、自分の学習データを使った機能** が
ほかにないかを調べ、作る価値の高い順に提案してください。

### いまあるもの（前提）

- 学習履歴 `/study/`（`src/app/study/StudyClient.tsx`）: 資格ごとに「解いた・正解・不正解・ブックマーク」の数と一覧、
  分野で絞り込み、メダル（銅＝前回不正解・銀＝正解・金＝銀の状態で再び正解）の枚数。
- 復習ドリル（`src/lib/review-drill.ts`）: 銅 → 銀 → 未挑戦の順に20問を続けて解く。
- 学習履歴の書き出し・読み込み（JSON。`src/components/ProgressBackup.tsx`）、続きから解くカード（`StudyResumeCard`）。
- 模擬試験（第1回無料・第2回有料）の結果画面: 分野ごとの正答率・最弱分野。結果は保存していない（途中保存だけ）。
- 本番形式テスト（20問・採点）、試験日・申込締切のカウントダウン、カレンダー登録（.ics / Google）。
- 保存しているデータ（すべて端末内の localStorage。`src/lib/study-progress.ts`）: 資格ごとに
  `correct` / `wrong` / `bookmarks`（問題の slug の配列）と `medals`（slug → 銅/銀/金）。
  **日時・回答の履歴・解いた時間・選んだ選択肢は持っていない。**
- 姉妹サービス「シカクモン Studio」: AI がその場で問題を作る・手元の教材から問題集を作る・忘却曲線で自動復習。
  機能が重なるものは、シカクモン側で作るか Studio へ送るかを分けて考える。

### 守ること（設計言語と約束）

- プライバシーポリシーで「学習データは端末内に保存され、サーバーには送信されません」と約束している。アカウントは無い。
  これを崩す提案は、崩す理由と代わりの約束まで書く。
- 控えめな広告・非AI的な編集トーン・事実の正確性。**捏造につながる提案はしない**（利用者の声・他の受験者の数字・
  合格率などは実在のものだけ）。
- 過去の判断: 掲示板・コイン制・段位・連続日数バッジは採らない（「金 120/240問」のような数字だけで見せる）。
  ゲーミフィケーションを提案するなら、このトーンに合う形まで落とす。

### 実測（GA4。数字はコード内コメントとユーザーの報告が一次情報）

- 2026-09-26〜10-23: 入口になったセッションのうち1問以上解いたのは 41%。資格トップ 44〜51%、調べ物のコラム 2〜14%。
- 問題を解いた人は1人あたり平均35問ほど解き、その8割強が「次の問題」も押す。問1を開いた人の約8割はその場で答える。
- 訪問はスマホ52%・PC47%。
- 模試を解き終えた人は、どの導線でも最も先へ進む層（90日で完了87人 → Studio 19人）。

### 調べる観点（それぞれ独立に）

1. **国内の無料問題サイト**（過去問道場シリーズ、Ping-t、宅建・FP・情報処理の「〜ドットコム」系 など）が、
   利用者自身のデータについて何を見せているか。
2. **学習アプリ・通信講座**（スタディング、Studyplus、Anki、Quizlet、Duolingo、オンスク、ユーキャン など）の、
   進捗・弱点・予測・目標・振り返りの機能。
3. **利用者の声**（アプリストアのレビュー、知恵袋、X、ブログ）: 問題演習サイト・アプリで「助かった」「欲しい」と言われているもの。
   出典の URL を必ず付ける。見つからなければ見つからないと書く。
4. **学習科学**: 想起練習・分散学習・交互練習・確信度の自己評価（メタ認知）・目標設定・フィードバックの時機。
   自分のデータを見せることが学習の成果や継続に効くという根拠と、逆効果になる条件。
5. **このサイトのデータと場面から逆算**: 初回・1問目のあと・35問ほど解いたあと・再訪・模試のあと・試験直前の各場面で、
   いまの機能で足りないもの。今のデータだけで作れるものと、端末内に新しい項目（日時など）を足せば作れるもの。

### 制約

- 読み取り専用で調べ、実装は指示があってから。
- 所見には根拠（`file:line`、出典 URL、実測の数字）を付ける。推測は「推測」と書く。
- 「UXを改善する」のような抽象論は書かない。どの画面に何を出すか、どのデータから計算するかまで書く。

### 出力

1. 冒頭に「もし1つだけ作るなら」を3行。
2. 提案を価値の高い順に。各提案に: 名前 / 利用者のどの場面か / 何を見せるか（画面と位置）/ 根拠（出典）/
   必要なデータ（今あるか・足すか）/ 工数(S/M/L) / 守ることとの関係 / 効果の測り方（GA4 イベント）。
3. 「作らないほうがよいもの」を理由つきで。
4. ユーザーに決めてもらうこと。

### 進め方

観点が5つあるので、Workflow で並列に調べ（観点ごとに1体）、候補をまとめて重複を除き、
候補ごとに「利用者の価値」「作れるか」「守ることとの相性・事業への効き方」の別々の目と、
反証役で評価してから、まとめる。最後に「抜けている観点・確かめていない主張」がないかを点検する。
