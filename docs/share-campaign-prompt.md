# 「X などでつぶやきたくなる企画」を設計するためのプロンプト

> 2026-10-25 作成。初回実施: 2026-10-25（結果は `docs/share-campaign-design.md`）。
> ユーザーの要望:「このサイトを X 等でつぶやきたくなる企画を考えたい。直近の一週間で一番正解率がいい、など、
> 利用者が利用者を運んでくる構成を作りたい」。

---

## プロンプト本文

あなたは学習サービスのグロース担当のデザイナーです。日本語でやり取りしてください。
シカクモン（shikakumon.com、リポジトリ `siken`）に、**利用者が自分から X などに投稿したくなり、その投稿を見た人が
シカクモンに来て、また投稿する**（利用者が利用者を運んでくる）企画と、その仕組みを設計してください。

### いまあるもの

- 模擬試験（第1回）の結果画面に X の投稿ボタンがある（`src/components/MoshiExam.tsx` の share 部分。
  文面は「◯◯の模擬試験(第1回)で 52/60問正解(87%)・合格圏でした。シカクモンで無料受験中」。GA4 `share_click`）。
- 合格報告（`/goukaku-houkoku/` → 運営宛メール → 運営が書き写して `/voice/` に掲載。謝礼なし。`docs/pass-report-ops.md`）。
- サーバー側の保存は今ほぼ無い（API は決済・合格報告のメール転送・模試リマインド登録（Studio の API に転送）だけ）。
  ページは Vercel 上の Next.js（ISR で1時間ごとに作り直し）。OG 画像は固定の `public/og-default.png`。
- 学習データは端末内だけ（`src/lib/study-progress.ts`）。アカウントは無い。

### 守ること・過去の判断

- プライバシーポリシー: 学習履歴（解いた問題の一覧・メダル・ブックマーク）は端末内だけに保存する。
  これを変える案は、変える理由・集めるもの・新しい約束の文面まで書く。
- 採らない方針にしてきたもの: 段位・利用者どうしの順位・連続日数バッジ・掲示板（`docs/affiliate-growth-audit.md` §5.2、
  `docs/self-data-features-research.md` の「作らないほうがよいもの」）。ユーザーの今回の要望（一週間で一番正解率がいい）は
  これと緊張関係にある。要望の狙い（自慢したい・競いたい・人を連れてくる）を満たす案を、方針の内側と、方針を変える場合の両方で出し、
  方針を変える案には何を変えるか・何が起きうるか（不正・荒れ・個人の特定）を書く。
- 投稿に見返りを出す企画は、ステマ規制（2023年10月〜の景品表示法の指定告示）と景品の上限に触れうる。合格報告に謝礼を出さない
  過去の判断もある。見返りを出す案は、法的な扱いを書く。
- 捏造しない（数字・利用者の声・他の利用者の成績は実在のものだけ）。控えめで非AI的な編集トーン。絵文字に頼らない。

### 調べること

1. 学習・クイズ・検定で、投稿が広がった企画の事例と、広がった理由（Wordle の共有グリッド、週替わり・日替わりの問題、
   友だちへの挑戦状リンク、Duolingo の週間リーグ、検定・模試の順位表、診断系 など）。出典つき。
2. X で資格の勉強をしている人が、実際に何を投稿しているか（勉強垢の学習記録、模試の結果、Studyplus の記録、合格報告、
   使っている問題サイトの紹介）。形式・ハッシュタグ・好まれる見た目。出典つき。
3. 仕組みの設計: 投稿 → 見た人が来る → その人も投稿する、の輪がどこで切れるか。投稿の文面・OG 画像・着地ページ・
   同じ問題で挑めるか。順位を出す場合の不正（端末内の数字は書き換えられる）と、その扱い。
4. このサイトで作れるか: OG 画像を結果ごとに作る（`next/og`）、URL に結果を載せる（サーバーに保存しない）、
   週替わりの問題セットを決める、匿名の集計をどこで持つか（GA4 / Vercel の KV など / Studio の API）。

### 出力

1. 冒頭に「もし1つだけやるなら」を3行。
2. 企画案を価値の高い順に。各案に: 名前 / 利用者の体験（見る → 解く → 投稿 → 見た人が来る、の流れ）/ 投稿の文面と見た目の例 /
   着地ページ / 必要な仕組み（サーバー保存の有無）/ 方針との関係（変えるなら何を）/ 不正・荒れ・法的な注意 /
   工数 S/M/L / 効果の測り方（GA4 と URL の utm）。
3. ユーザーの要望「一週間で一番正解率がいい」への答え（そのまま作る場合の形と条件、代わりの形）。
4. 作らないほうがよいもの。
5. ユーザーに決めてもらうこと。
